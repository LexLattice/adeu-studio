## Alignment Judgment

`PB-CASE-EXPANSION-0-A` created the non-executing source-pool and eligibility
boundary:

- one local case expansion request over released local cleanroom substrate;
- source pool manifest with concrete refs, origin posture, visibility posture,
  derived-summary policy, source identity hashes, and candidate case ideas;
- eligibility review for candidate case ideas;
- expansion control contract;
- non-authority guardrail.

It kept local case supply separate from execution, scoring, official
participation, and model ranking. It rejected hidden, forbidden, postmortem,
original-source-derived, decompilation-derived, internet-derived,
external-repo-derived, official-evaluator-derived, and support-only source
rows as eligibility basis. It made no-derived-summary laundering a named
validation law, required dedupe/novelty posture for candidate case ideas, and
kept representativeness as `not_representative_benchmark_sample`.

`PB-CASE-EXPANSION-0-B` turned A-eligible case ideas into plan-only local
case definitions:

- local case blueprint;
- cleanroom evidence pack;
- probe contract;
- oracle boundary;
- contamination screen.

It kept behavior obligations source-bound, kept probe commands argv-shaped and
non-executing, kept the oracle local-only rather than official task truth, and
kept contamination screening explicit. Review hardening added stronger hash
bindings, clearer blueprint disjointness, and stricter probe/oracle/hidden
evidence boundaries.

`PB-CASE-EXPANSION-0-C` registered and summarized validated local case
lineages:

- local case lineage registration;
- expansion readiness summary;
- matrix candidate handoff;
- family closeout alignment.

Review hardening required per-surface closeout refs, complete B component hash
bindings, clean contamination screen binding, complete local probe/oracle
coverage, disjoint ready/blocked coverage, duplicate logical-key rejection,
inventory-only ready counts, and pressure-only matrix candidate handoff rows.

The three slices align:

- A source-pool eligibility is not blueprinting, execution, scoring, matrix
  inclusion, official participation, or model-ranking authority;
- B blueprints consume released A rows and cannot select new source pools
  directly;
- B probe contracts are plans only and cannot execute commands or grant run
  authority;
- B oracle boundaries are local blueprint oracles only, not official
  ProgramBench truth;
- B contamination screens fail closed and reject hidden, forbidden,
  postmortem, source-derived, evaluator-derived, decompilation-derived,
  internet-derived, and external-repo-derived facts;
- C lineage registration requires released A/B refs, complete component hash
  binding, clean contamination, and complete probe/oracle coverage;
- C readiness counts are inventory accounting only and cannot become pass
  rate, solve rate, success rate, benchmark score, model score, official
  success rate, or leaderboard metric;
- C matrix candidate handoff rows are pressure-only and cannot directly
  include a case in a matrix or authorize batch execution;
- C family closeout closes exactly `PB-CASE-EXPANSION-0-A/B/C`;
- official ProgramBench participation, official runner/evaluator integration,
  hidden tests, source lookup, benchmark submission, benchmark scoring,
  baseline comparison, model ranking, generated official submissions,
  unbounded command execution, batch execution authority, direct matrix
  inclusion, second retry authority, retry-chain authority, runtime
  transition, product authority, graph-memory authority, release authority,
  recursive-policy authority, and future-family selection remain unselected.
