# Architecture ADEU Semantic Declaration Meta-Loop Family v0

Status: architecture / decomposition note for planned `V85`.

Authority layer: architecture / decomposition.

This architecture note does not authorize semantic declaration runtime,
obligation expansion, implementation, code edits, command execution, tool
invocation, target mutation, worker dispatch, PR creation, commit, merge,
release, product authority, graph-memory authority, recursive policy
amendment, or future-family selection by itself. It defines the intended
family boundary for `V85` so starter locks can select bounded review slices
without turning semantic declaration review into sovereign process control.

## Family Thesis

`V85` should institutionalize the first office of the canonical ADEU semantic
declaration meta-loop:

```text
natural task / code context
  -> typed semantic declaration
  -> canonical pointer lookup
```

The practical goal is not to make the resident model reason harder. The
practical goal is to put the resident model inside a deterministic institution
where it performs bounded local work:

```text
semantic pointer obedience
artifact-shape obedience
bounded local judgment
declared uncertainty
no unauthorized transition
```

The harness owns sequence meaning. The model owns bounded local judgment and
typed artifact production.

Controlling invariant:

```text
V85 may make semantic declaration and canonical pointer lookup reviewable,
but it may not expand declarations into implementation authority, worker
execution, runtime transition, product authorization, release, graph-memory
authority, recursive policy amendment, or later-family selection.
```

Validator spine:

```text
semantic declaration != semantic authority
canonical lookup != natural-language truth
obligation-family lookup != obligation expansion
ready for later review != V86 selected
```

## General Frame

The family is a bridge between two already-developed tracks:

- `V83` and `V84` made the intent-to-implementation-spec and
  work-packet-activation-review pipeline explicit.
- `docs/support/ARCHITECTURE_ADEU_CANONICAL_SEMANTIC_DECLARATION_META_LOOP_v0.md`
  states the broader circuit: semantic declaration, canonical lookup,
  obligation expansion, bounded execution, evidence, audit, and deterministic
  closeout routing.

`V85` should not jump to the whole circuit. It should type the declaration and
lookup substrate that later families can consume.

The resident model should not be asked:

```text
Can you reconstruct the whole institution and choose the next action?
```

It should be asked:

```text
Can you identify the active pointer?
Can you emit the required artifact shape?
Can you route uncertainty into the declared uncertainty slot?
Can you stop when the schema says stop?
```

## Source Stack Consumed

`V85` consumes the full `V68` through `V84` substrate. Most importantly, it
consumes:

- `V83` semantic intent contracts, semantic edge decompositions, artifact
  obligation maps, projection packets, quality gates, and work-packet
  handoffs as upstream context;
- `V84` activation-review requests, source indexes, scope contracts, target
  boundaries, validation evidence plans, readiness summaries, and handoffs as
  downstream pressure showing why a more canonical semantic declaration office
  is needed;
- the combined `V68` through `V84` dogfood artifacts as support evidence that
  the closed review pipeline composes;
- the post-`V84` roadmap and canonical semantic declaration meta-loop support
  note as planning/support doctrine.

No upstream stage becomes semantic declaration authority, obligation expansion
authority, implementation authority, runtime authority, product authority, or
future-family selection by being consumed.

## Family Slices

### `V85-A`: Declaration Request Intake

Starter surfaces:

- `repo_turn_semantic_declaration_request@1`
- `repo_semantic_declaration_source_index@1`
- `repo_semantic_declaration_non_authority_guardrail@1`

Purpose:

- record source-bound semantic declaration-review requests over released
  `V84-C` substrate, operator task context, repo context, support doctrine,
  and absence posture;
- assign a stable `semantic_declaration_session_ref` across request,
  declared act, witness, competency, lookup, summary, and handoff rows;
- split request recordability from declaration-review eligibility;
- split declaration candidate status, canonical lookup status, and selected
  declaration status;
- make source witnesses, negative cues, and resident-model competencies
  row-shaped instead of prose-only;
- preserve selected, ambiguous, abstain, registry-gap, malformed, and blocked
  binding postures;
- preserve non-authority guardrails before canonical lookup registries,
  obligation expansion, evidence contracts, audit taskpacks, summaries, or
  handoffs exist.

Forbidden:

- canonical lookup indexes;
- operator/class registries;
- obligation-family registries;
- pointer lookup fixtures;
- obligation expansion, evidence contracts, edge probe plans, audit reports,
  deterministic closeout routing, implementation, command execution,
  work-packet activation, graph authority, or `V86` selection.

### `V85-B`: Canonical Lookup And Registry Review

Later surfaces:

- `repo_canonical_meta_lookup_index@1`
- `repo_semantic_operator_class_registry@1`
- `repo_obligation_family_registry@1`
- `repo_semantic_pointer_lookup_fixture@1`

Purpose:

- make the canonical meta-list reviewable as lookup records, operator/class
  registry rows, obligation-family registry rows, and pointer lookup fixtures;
- separate operator registry semantics from class registry semantics, so
  authority-adjacent entries such as `GATE`, `router.dispatcher@v1`,
  `state.transition@v1`, and `worker.taskpack@v1` remain declaration/lookup
  entries rather than runtime behavior;
- encode pointer grammar and pointer competency horizons so opaque pointer
  success proves pointer obedience only;
- record obligation-family relation kinds without expanding obligation
  families;
- prove exact pointer handling before natural binding is trusted;
- preserve order, duplicates, unknown-pointer abstention, registry gaps, and
  conflict routing;
- keep obligation families as lookup results and not as executed obligations.

Forbidden:

- obligation expansion bundles;
- evidence contracts or edge probe plans;
- reviewer taskpacks or audit reports;
- state transition tables or deterministic closeout execution;
- runtime behavior, implementation, or product authority.

### `V85-C`: Declaration Readiness And Handoff

Later surfaces:

- `repo_semantic_declaration_review_summary@1`
- `repo_post_semantic_declaration_review_handoff@1`
- `repo_semantic_declaration_family_closeout_alignment@1`

Purpose:

- summarize released `V85-A` and `V85-B` substrate;
- say whether declarations are ready, warning-ready, blocked, registry-gap,
  ambiguity-blocked, future-family-only, or out of scope for later obligation
  expansion review;
- enforce that every summarized declaration, lookup, registry, obligation,
  and handoff row shares the same semantic declaration session and candidate
  lineage;
- keep warning-ready posture narrow so ambiguity, registry gaps, missing
  witnesses, unknown pointers, support-only sources, invented classes, lookup
  conflicts, and missing guardrails remain blockers;
- sequence handoffs so evidence, edge-probe, audit, and closeout-transition
  pressure normally remain downstream of future obligation expansion review;
- hand off future obligation-expansion, evidence-contract, edge-probe,
  audit-taskpack, closeout-transition, implementation-lock, Morphic UX, direct
  OAI, or meta-orchestrator workflow pressure without selecting it;
- close `V85` as semantic declaration and canonical lookup review only.

Forbidden:

- expanding obligations into required implementation work;
- producing evidence contracts, edge probe plans, reviewer taskpacks, audit
  reports, deterministic transition tables, implementation locks, runtime
  transitions, or product decisions;
- selecting `V86`.

## Required Boundary Distinctions

`V85` must keep these distinctions machine-checkable:

- semantic declaration request is not semantic declaration authority;
- source-bound declaration is not obligation expansion;
- canonical pointer lookup is not implementation authority;
- canonical pointer lookup is not natural-language truth;
- operator/class registry row is not runtime class behavior;
- obligation-family registry row is not an executed obligation;
- obligation-family lookup is not obligation expansion;
- opaque pointer success is not natural-language semantic truth;
- resident-model output is candidate-only until source-bound and validated;
- ambiguity is not selected binding;
- abstain is not failure to comply;
- registry gap is not permission to invent a class;
- support doctrine is not eligibility by itself;
- ready for later obligation-expansion review is not `V86` selection;
- Morphic UX, direct OAI, and meta-orchestrator examples are support context,
  not runtime implementation authority;
- handoff is not later-family completion.

## Negative Laws

- "The model selected `CREATE ui.menu@v1`" is not "the menu can be built".
- "The lookup returned obligation families" is not "obligations have been
  expanded, evidenced, or audited".
- "The opaque pointer test passed" is not "natural binding is semantically
  correct".
- "The support doctrine names a class" is not "the current turn is eligible".
- "The declaration is ready for later review" is not "`V86` is selected".

## O/E/D/U Boundary

`V85` primarily establishes O-binding:

```text
operator + object/function class + target/context refs + source witnesses
```

It may name future E/D/U pressure, but it does not instantiate it:

- E: evidence contracts and admissible witness rules remain later-family
  pressure.
- D: obligation expansion remains later-family pressure.
- U: closeout transition and utility routing remain later-family pressure.

This boundary is why `V85` should precede `V86` through `V88`.

## Resident-Model Competency Contract

The model-side competency expected by `V85` is modest and strict:

- identify the active semantic pointer or declared loop state;
- consume only declared inputs for that state;
- emit the required artifact shape;
- preserve order, duplicates, refs, and declared uncertainty fields;
- refrain from inventing a different class, obligation, artifact, or
  transition;
- route ambiguity, unknown pointers, and malformed inputs into declared
  uncertainty / abstain / registry-gap slots;
- stop when the schema or transition table stops.

Any implementation of `V85` should prefer fail-closed validation over helpful
repair. Unknown pointers and ambiguous natural bindings should become explicit
review rows, not invented canonical classes.

## Package Boundary

Expected implementation ownership remains `packages/adeu_repo_description`.
`V85` describes repo-grounded declaration and lookup review metadata. A later
live meta-orchestrator runtime, resident-agent harness, direct provider
runtime, Morphic UX implementation, product UI, graph runtime, or release
automation layer should split away rather than expanding repo-description by
implication.
