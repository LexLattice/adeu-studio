## 5. What v42 Proves

v42 proves five things.

### 5.1 The blind path had correctly localized the tail

By v41, the active parents were already known:

```text
XML / HTML formatter and recovery
XPath / CSS selector sublanguages
JSON tree and route behavior
I/O and fatality boundaries
fixture corpus exactness
```

The v42 ownership table did not discover a new high-level program class. It confirmed that the remaining tail sat below known parents.

### 5.2 The findability gate was correctly triggered

The v40/v41 conclusion was:

```text
Stop asking what parent was missed.
Ask what evidence source can distinguish terminal leaves.
```

v42 validates that rule. The successful evidence source was not more generic descent; it was source-tail / fixture-corpus / host-library parity.

### 5.3 Source-tail can be clean if explicitly labeled

The source-tail path preserved every previous locked probe gate:

```text
v35: 176 / 176
v36:  32 / 32
v39:  33 / 33
v40:  40 / 40
v41:  49 / 49
```

That matters because source-tail repair did not erase the blind reconstruction evidence. It created a separate witness that preserved previous contracts and then closed the tail with stronger authority.

### 5.4 Target-substrate adaptation is a legitimate witness-bundle operation

The implementation posture says upstream semantics were preserved while only the build floor and dependency floor were adapted to the ProgramBench Go 1.21 cleanroom, with dependencies vendored.

This should be classified under:

```text
TARGET_SUBSTRATE_BUILD_FLOOR_ADAPTATION
```

not under product-behavior rewrite.

### 5.5 Corpus parity is sometimes the final theorem fragment

At high score, synthetic microgrammar atoms stopped moving many rows. The final target behavior was bound to:

```text
source-root fixture morphology
upstream tokenizer / parser / serializer policy
host-library selector behavior
official branch golden files
```

That is not a failure of ontology. It is a proof that some terminal leaves are corpus/library-defined.

## 6. What v42 Does Not Prove

v42 does not prove:

```text
blind first-pass reconstruction can reach 100 on xq;
pre-eval descent alone can infer all XML/HTML/XPath byte behavior;
source facts should be available to the implementation worker in ordinary clean runs;
fixture-corpus parity should be used before blind findability saturates;
all structured document tasks require source-tail.
```

The correct claim is narrower and stronger:

```text
After salience and descent gates have saturated, and after the residual tail is
owned by exact host-library / source-fixture / corpus-byte compatibility, a
labeled source-tail path is the right escalation method.
```

## 7. Proposed v43 Meta-Program Additions

### 7.1 `SOURCE_TAIL_ESCALATION_AUTHORIZATION_GATE`

Trigger:

```text
high-score tail remains after salience, descent, targeted microgrammar,
and findability gates;
remaining owners are known;
public/reference probes have saturated;
residual rows require host-library, source-root fixture, or official-corpus parity.
```

Required row:

```yaml
source_tail_escalation:
  triggering_run_ref: string
  prior_blind_gates_green: []
  remaining_tail_count: int
  known_owner_nodes: []
  public_findability_status: saturated | still_blind_findable | mixed
  requested_evidence_source:
    - source_tail
    - fixture_corpus_tail
    - host_library_equivalence
    - target_substrate_dependency
  non_laundering_statement: required
  allowed_scope: []
  forbidden_use: []
  posture: blocked | authorized_source_tail | authorized_fixture_corpus | mixed
```

Blocking rule:

```text
Source-tail access is not authorized merely because official score is below 100.
It is authorized only when the residual tail has been localized and blind/public
methods are saturated or explicitly lower-yield for the owner.
```

### 7.2 `HOST_LIBRARY_EQUIVALENCE_WITNESS_GATE`

Trigger:

```text
behavior depends on parser, selector, renderer, serializer, query engine,
codec, formatter, terminal library, DB driver, shell, or OS library.
```

Required row:

```yaml
host_library_equivalence:
  behavior_owner: string
  target_library_or_dependency: string
  public_probe_coverage: []
  source_tail_evidence: []
  target_substrate_build_evidence: []
  divergence_from_local_heuristic: []
  equivalence_status:
    public_approximation | source_tail_required | equivalent | incompatible | deferred
```

Rule:

```text
At tail stage, replacing a host library with heuristic reimplementation is not
closed unless the heuristic is proved equivalent on the active corpus and
microgrammar axes.
```

### 7.3 `FIXTURE_CORPUS_PARITY_GATE`

Trigger:

```text
remaining rows compare against golden files, corpus fixtures, branch test/data,
source-root examples, or realistic morphology distributions not reproduced by
synthetic atoms.
```

Required row:

```yaml
fixture_corpus_parity:
  corpus_ref: string
  owner_nodes: []
  corpus_morphology_axes: []
  synthetic_probe_gap: string
  source_or_branch_fixture_refs: []
  parity_status: not_started | partial | green | skipped_rows_documented
```

Rule:

```text
Formatter/serializer tails cannot be declared gold-closed from atom probes if
the official corpus includes morphology combinations not represented by those
atoms.
```

### 7.4 `SOURCE_TAIL_WITNESS_SEPARATION_GATE`

Trigger:

```text
source-tail implementation diverges from prior blind candidate.
```

Required row:

```yaml
source_tail_witness_separation:
  blind_witness_ref: string
  source_tail_witness_ref: string
  shared_probe_gates_preserved: []
  changed_authority_layer: true
  allowed_backport_to_blind_schema:
    - method_gate
    - owner_mapping
    - findability_rule
    - evidence_source_rule
  forbidden_backport_to_blind_schema:
    - source-derived expected bytes
    - source-derived hidden fixture facts
    - direct implementation-specific shortcuts
```

Rule:

```text
A source-tail witness can solve the task and improve future method, but its
source-derived facts must not be relabeled as blind reconstruction evidence.
```

Rule:

```text
Build-floor adaptation is allowed only if separated from product-semantic repair

```

## 11. Main Meta-Program Lesson

The strongest reusable lesson is:

```text
Not every remaining failure is findable at the same evidence layer.
```

Earlier xq passes showed that:

```text
salience-breaking finds omitted low-salience axes;
descent-completeness finds under-terminalized active parents;
second descent squeeze finds additional public microgrammar siblings;
findability audit detects saturation;
source-tail closes host-library and fixture-corpus exactness.
```

So the mature orchestrator should not keep repeating the same kind of pass. It should select the evidence source appropriate to the tail:

```text
omission tail          -> salience adversary
under-descended parent -> closure matrix descent
microgrammar tail      -> targeted public reference matrix
corpus/library tail    -> source-tail / fixture-corpus / library equivalence
substrate tail         -> target dependency/build-floor proof
```
