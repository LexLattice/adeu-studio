## Purpose

Freeze the bounded `V85-A` starter slice so the repo can translate released
`V84-C` work-packet activation-review substrate, current operator / repo task
context, and canonical semantic declaration support doctrine into
source-bound semantic declaration-review request records.

`vNext+239` authorizes docs plus the next implementation path over the
existing repo-owned `adeu_repo_description` package. It does not authorize
`V85-B`, `V85-C`, canonical lookup indexes, operator/class registries,
obligation-family registries, pointer lookup fixtures, declaration summaries,
post-declaration handoffs, obligation expansion, evidence contracts, edge
probe plans, reviewer taskpacks, audit reports, deterministic transition
tables, implementation locks, work-packet activation, implementation, code
edits, command execution, tool invocation, target mutation, worker dispatch,
runtime transition, Morphic UX runtime change, direct OAI runtime behavior,
PR creation, commit, merge, release, product authorization, graph-memory
authority, recursive policy amendment, or selection of `V86`.

Controlling invariant:

```text
V85 may make semantic declaration and canonical pointer lookup reviewable,
but it may not expand those declarations into implementation authority,
worker execution, runtime transition, product authorization, release,
graph-memory authority, recursive policy amendment, or later-family selection.
```

The active `V85-A` implementation may add its own schema, model, validator,
fixture, and test files under this lock. That implementation work is distinct
from running a semantic declaration office or executing any downstream loop
transition. `V85-A` may make semantic declaration pressure visible; it must not
record that a declaration is canonical, obligation-expanded, implementation
ready, runtime-authorizing, or later-family-selecting.

## Required Deliverables / Exit Conditions

  - `repo_turn_semantic_declaration_request@1`
  - `repo_semantic_declaration_source_index@1`
  - `repo_semantic_declaration_non_authority_guardrail@1`
- deterministic reference and reject fixtures for the bounded `V85-A` starter
  family only;
- validators that prove:
  - every declaration request references known source rows and guardrail rows;
  - `semantic_declaration_session_ref` is stable across request, act, witness,
    competency, and guardrail rows;
  - recordability remains distinct from eligibility;
  - `V85-A` creates candidates only and does not select canonical
    declarations;
  - generated declaration candidates remain candidate-only unless source-bound
    by witnesses and provenance;
  - support-only source rows cannot make a request eligible;
  - ambiguous, abstain, malformed, and registry-gap states fail closed;
  - opaque pointer success cannot prove natural binding correctness;
  - unknown classes are not repaired into nearest registry classes;
  - negative cues route implementation, execution, obligation expansion,
    product, release, runtime, class-invention, and later-family pressure into
    guardrail / future-family posture;
  - no `V85-B`, `V85-C`, obligation expansion, implementation, runtime,
    product, graph, recursive-policy, or `V86` rows ship in this slice.
